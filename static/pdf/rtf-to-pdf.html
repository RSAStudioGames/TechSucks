Frequently Asked Questions

Why does the first RTF file take longer to convert?

The converter is LibreOffice compiled to WebAssembly, and the engine is about 77 MB compressed. It's downloaded and started the first time you convert in a session; after that, each file takes only a few seconds.

What RTF formatting is preserved in the PDF?

Font styles such as bold and italic, paragraph alignment, lists, tables, and embedded images come through as they would if you exported the file from LibreOffice Writer. Embedded OLE objects, such as inserted spreadsheets, may not render fully.

Will my fonts look the same?

Only fonts bundled with the engine are available, which covers common Latin, Arabic, and Hebrew faces. Fonts that aren't bundled are replaced with the closest substitute, so line breaks and spacing can shift slightly.

Can I convert many RTF files at once?

Yes. One file downloads as a PDF with the same base name; several files download together as rtf-converted.zip with one PDF per file, and duplicate names are numbered automatically.

What's the difference between this and Word to PDF?

Both use the same LibreOffice engine and produce the same result for RTF. Word to PDF also accepts .doc, .docx, and .odt, so use it when you have a mix of formats in one batch.

Does it handle RTF from WordPad, TextEdit, or legal and medical software?

RTF written by any standard word processor converts, including files from WordPad, TextEdit, and exports from records systems. Proprietary extensions inside such files may be dropped, but the text and standard formatting still convert.

What about text in Chinese, Japanese, Korean, or Indic scripts?

Those fonts aren't bundled with the browser engine, so text in these scripts may render with a fallback font or as boxes. Latin, Arabic, and Hebrew scripts are covered.

Is my document sent to a LibreOffice server?

No. The whole LibreOffice engine runs inside your browser tab as WebAssembly. Your file is converted locally, and the only thing downloaded is the engine itself.
