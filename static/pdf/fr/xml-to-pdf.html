Questions fréquemment posées

Comment l’outil décide-t-il de l’aspect du PDF ?

Il analyse le XML, regroupe les éléments frères répétés par nom de balise et rend chaque groupe sous forme de tableau avec une colonne par élément enfant, en utilisant les noms d’éléments comme en-têtes. Si la racine n’a pas d’enfants répétés, vous obtenez un tableau à deux colonnes Propriété et Valeur. Le résultat est en A4 paysage avec le nom de l’élément racine comme titre.

Quel type de XML fonctionne le mieux ?

Du XML de type données : des enregistrements avec le même ensemble d’éléments enfants répétés sous un même parent, comme des exports de base de données, des lignes de facture, des flux de produits, des flux RSS ou des sitemaps. Le XML très imbriqué ou de type document est aplati : les valeurs imbriquées sont donc réunies dans une seule cellule et perdent leur hiérarchie.

Pourquoi ai-je une erreur XML non valide ?

Le fichier n’est pas bien formé : une balise non fermée, un élément racine manquant, un caractère & ou < non échappé, ou un mauvais encodage. Le message inclut la raison donnée par l’analyseur ; corrigez donc le fichier dans un éditeur ou un validateur et réessayez.

Les attributs XML sont-ils inclus dans le PDF ?

En partie. Dans la vue tableau, seuls les éléments enfants deviennent des colonnes ; les attributs des enregistrements répétés ne sont donc pas affichés. Dans la vue Propriété et Valeur pour une racine sans répétition, les attributs sont listés après les valeurs des enfants.

Puis-je convertir plusieurs fichiers XML à la fois ?

Oui. Ajoutez plusieurs fichiers et ils sont convertis en un seul lot dans xml-to-pdf.zip avec un PDF par fichier. Un fichier unique est téléchargé directement avec le même nom de base et l’extension .pdf.

Applique-t-il ma feuille de style XSLT ou CSS ?

Non. Les instructions de feuille de style et les déclarations DOCTYPE sont supprimées avant l’analyse, et la mise en page est générée à partir de la seule structure des données. Si vous avez besoin du rendu stylisé, ouvrez le XML dans un navigateur qui applique la feuille de style et imprimez-le en PDF à partir de là.

Le texte en chinois, arabe, cyrillique ou autres écritures non latines s’affichera-t-il ?

Pas de façon fiable. Le PDF est construit avec la police Helvetica standard de jsPDF, qui couvre les caractères latins ; le texte dans d’autres écritures peut donc s’afficher avec des caractères incorrects ou manquants.

Le fichier XML est-il envoyé pour être converti ?

Non. L’analyse utilise un analyseur XML JavaScript et le PDF est généré avec jsPDF, tous deux dans votre navigateur ; les factures, journaux de transactions et autres données sensibles du fichier ne quittent donc jamais votre appareil.
