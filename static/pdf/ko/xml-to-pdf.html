자주 묻는 질문

도구는 PDF의 모양을 어떻게 결정하나요?

XML을 분석해 반복되는 형제 요소를 태그 이름별로 묶고, 각 그룹을 자식 요소마다 열이 하나씩 있는 표로 렌더링하며 요소 이름을 머리글로 씁니다. 루트에 반복되는 자식이 없으면 속성과 값의 두 열짜리 표가 나옵니다. 결과물은 가로 방향 A4이며 루트 요소의 이름이 제목이 됩니다.

어떤 종류의 XML이 가장 잘 맞나요?

데이터 형태의 XML이 가장 좋습니다. 데이터베이스 내보내기, 송장 항목, 상품 피드, RSS 피드, 사이트맵처럼 같은 자식 요소 집합을 가진 레코드가 하나의 부모 아래 반복되는 경우입니다. 깊게 중첩되었거나 문서 형태의 XML은 평탄화되어 중첩된 값이 하나의 셀로 합쳐지고 계층이 사라집니다.

잘못된 XML 오류가 나오는 이유는 무엇인가요?

파일의 형식이 올바르지 않습니다. 닫히지 않은 태그, 없는 루트 요소, 이스케이프되지 않은 & 또는 < 문자, 잘못된 인코딩 등이 원인입니다. 메시지에 파서가 알려 주는 이유가 포함되므로 편집기나 검증기에서 파일을 고친 뒤 다시 시도하세요.

XML 속성도 PDF에 포함되나요?

부분적으로만 포함됩니다. 표 보기에서는 자식 요소만 열이 되므로 반복되는 레코드의 속성은 표시되지 않습니다. 반복되지 않는 루트의 속성과 값 보기에서는 속성이 자식 값 뒤에 나열됩니다.

XML 파일 여러 개를 한 번에 변환할 수 있나요?

네. 여러 파일을 추가하면 한 번에 변환되어 파일당 PDF 하나씩 담긴 xml-to-pdf.zip이 됩니다. 파일 하나는 같은 기본 이름에 .pdf 확장자로 바로 다운로드됩니다.

내 XSLT 스타일시트나 CSS를 적용하나요?

아니요. 스타일시트 지시문과 DOCTYPE 선언은 분석 전에 제거되며 레이아웃은 데이터 구조만으로 생성됩니다. 스타일이 적용된 모습이 필요하면 스타일시트를 적용하는 브라우저에서 XML을 열고 거기서 PDF로 인쇄하세요.

중국어, 아랍어, 키릴 문자 등 라틴 문자가 아닌 텍스트도 표시되나요?

확실하지 않습니다. PDF는 라틴 문자를 지원하는 jsPDF의 표준 Helvetica 글꼴로 만들어지므로, 다른 문자로 된 텍스트는 잘못된 글자나 빠진 글자로 표시될 수 있습니다.

변환을 위해 XML 파일이 업로드되나요?

아니요. 분석은 JavaScript XML 파서로, PDF 생성은 jsPDF로 모두 브라우저 안에서 이루어지므로 파일에 든 송장, 거래 로그 등 민감한 데이터가 기기 밖으로 나가지 않습니다.
