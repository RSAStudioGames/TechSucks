常見問題

我要如何檢查已簽署的 PDF 在簽署後是否被更動過？

上傳 PDF 後驗證會自動開始。對於每個簽章，工具會對簽章涵蓋的位元組計算雜湊，與簽章內儲存的摘要比對，接著以簽署者的公開金鑰驗證簽章；涵蓋位元組的任何變動都會使狀態變為「無效」，並在卡片上顯示原因。檔案中的每個簽章都有各自的卡片，頂端的摘要會統計找到幾個。

「有效」、「無效」與「未驗證」各代表什麼？

「有效」表示簽章已通過密碼學驗證、涵蓋整個檔案，且使用安全的摘要。「無效」表示驗證已執行但失敗，例如位元組被更動或金鑰不符。「未驗證」表示簽章使用了工具無法檢查的演算法，例如 Ed25519 或 SM2，所以在依賴它之前，請用 Adobe Acrobat 或 openssl 確認。

支援哪些簽章演算法？

使用 PKCS#1 v1.5 填充的 RSA、RSA-PSS，以及 P-256、P-384 與 P-521 曲線上的 ECDSA，搭配 SHA-224、SHA-256、SHA-384 或 SHA-512 摘要。以 MD5 或 SHA-1 雜湊的簽章會被標示為「不安全的摘要」狀態，且永遠不會被回報為有效，因為這兩種演算法都已有公開的碰撞攻擊。

為什麼卡片顯示「簽署者身分未驗證」？

工具沒有內建的憑證授權單位清單，所以單靠它只能確認簽章完整，無法確認憑證背後是誰。請上傳您組織的根憑證或中繼憑證（.pem、.crt、.cer 或 .der 檔案），驗證就會重新執行：憑證與它相符或能鏈結回它的簽章會獲得「受信任」標章，摘要也會把這些計為有效。

部分涵蓋是否表示文件遭到竄改？

這表示在套用此簽章之後，有位元組被附加到檔案中。被簽署的部分仍然完整，所以工具會顯示「簽署後已修改」警告，而不是將簽章標為無效。這本身不能證明遭到竄改：第二個簽章或增量儲存都會產生相同結果，而且只有最後加入的簽章能涵蓋整個檔案。請把它當作需要查看新增內容的理由。

它會檢查簽署憑證是否已被撤銷嗎？

不會。工具會檢查憑證的有效日期、依您提供的憑證檢查信任鏈，以及簽章的密碼學完整性，但不會查詢 OCSP 回應端或憑證撤銷清單。若需要撤銷檢查，請在可連線網路的桌面工具中驗證檔案。

如果憑證在文件簽署後才過期會怎麼樣？

到期是依今天的日期判斷，所以憑證若已超過「有效期限」日期，會顯示「憑證已過期」狀態，即使簽章本身檢查無誤，也不會在摘要中計為有效。請比較卡片上的「簽署時間」與「生效日期」及「有效期限」，以了解簽署當時憑證是否有效。

已簽署的 PDF 或我信任的憑證會被上傳到任何地方嗎？

不會。簽章解析與密碼學檢查使用 node-forge 與 Web Crypto API 在您的瀏覽器中執行，所以文件與您加入的任何憑證都會留在您的裝置上。
